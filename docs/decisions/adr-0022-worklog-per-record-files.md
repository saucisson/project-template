# ADR-0022: Worklog as per-record files (worklog v2)

- Status: accepted
- Date: 2026-11-12

## Context

`WORKLOG.md` was a single append-only file, prepended by every pull
request in a format learned by reading the file. Three costs appeared
as instances grew: accidental reading of the monolith by the agent
(context and token drain), unbounded growth (one instance reached
~106 KB), and rebase conflicts on every parallel branch; plus a
duplication with the pull request body (Changes, Testing evidence,
Judgement calls).

## Options considered

- **Keep the monolith** (rejected): the costs above grow with the
  project; the audit trail should not tax every session.
- **No worklog at all** (rejected): the end-of-day human audit loses
  its chronological record; the pull requests alone do not show what
  direct commits on `daily` did.
- **One file per record, driver-generated** (chosen): bounded file
  sizes, no read path for agents, no merge conflicts between
  concurrent branches.

## Decision

One file per record in `docs/worklog/`, human-facing only, generated
by the driver:

- `YYYY-MM-DD-pr-<N>.md`: one index card per pull request, generated by
  `make pr`, committed on the PR branch (`worklog: PR #N`).
- `YYYY-MM-DD-direct-<slug>.md`: one entry per direct commit on `daily`,
  created from `docs/worklog/_template.md` in the same commit.
- `README.md` and `_template.md` document the folder for the human
  reader; agents never read them.

No agent reads `docs/worklog/`. The evening audit goes through
`make day-report`, which lists the day's entries.

## Consequences

- The monolith and its rebase conflicts are gone.
- All agent-side reading of the worklog is gone (context savings).
- The `make pr` driver generates the entry without agent intervention.
- Direct commits carry their template entry in the same commit.
- The reviewer checks the entry's presence and coherence in the diff,
  not its prose quality against a format learned from the file.

## Precedence

This ADR takes precedence over the worklog clauses of ADR-0009,
ADR-0010 and ADR-0017, as well as over any clause of the following
constitutional files that instructs writing or reading `WORKLOG.md`:

- `AGENTS.md` (honesty rules, session context, end-of-day audit)
- `docs/agents/developer.md` (reporting section, session continuity,
  recovery)
- `docs/agents/orchestration.md` (S3, S7, S8)
- `docs/branching.md` (end-of-day step)
- `docs/review-checklist.md` (S7)
- `.vibe/prompts/night-issue.md`, `.vibe/prompts/night-auto.md`
