# feat(G4/N4): the english-only front and the commit-subject hook (ADR-0008)

- Date: 2026-11-25
- Type: feature (driver tooling, Python) plus template-level wiring; no constitutional change, G4/N4 already record the convention
- Scope: scripts/english.py (new), scripts/tests/test_english.py (new), scripts/__main__.py (dispatch), Makefile (english-only target, check chain, commit-msg hook-type install), .pre-commit-config.yaml (english-subject local hook), .github/workflows/ci.yml (quality job front step)
- Motive: G4 makes English the language of every development artifact and N4 places the check at the template level, commit-msg hook included; written French can be accent-free, so a bare accented-character grep alone does not enforce the convention - the front pairs the accented signal with an unaccented-French signal, adapted from the lisage checker (saucisson/lisage/scripts/english_only.py, issues #104 and #110) and scoped to this repository
- Evidence: the port keeps the lisage signal and corpus doctrine (accented characters everywhere, French identifier stems over Python identifiers, French stop-words in comments and plain-text config only, Markdown code formatting skipped) and drops the Rust-specific string and comment handling; the two py2-style except clauses of the source file were fixed during the port and the stray split() token of its lexicon dropped; the f-string middles of PEP 701 tokenization join the string corpus, so a French label inside an f-string cannot hide; eighteen unit tests live in scripts/tests/test_english.py and a local stdlib verification ran 29 checks green against the assembled module, subject mode included; the local run also scanned the whole assembled branch tree with the front itself: 0 offenders over the 64 in-scope files (the scope globs spell docs/* and docs/**/* explicitly, because a bare docs/** matches no file at all under pathlib glob semantics); the local run diverged from the pushed files only in the import region (Python 3.12 eager annotations against the house TYPE_CHECKING pattern for 3.15: only the local copies carry from __future__ import annotations)
- Known limits: Markdown is scanned for the accented signal alone, so accent-free French prose in prose files stays under the stop-word radar (lisage doctrine: docs quote code and identifiers too much for whole-word lists there); the lexicon keeps the lisage calibration, instances extend it as their own renames surface new stems; the hook checks the subject line only, the message body stays review material; the ruff format of the new modules could not be computed locally (no ruff in the sandbox), so the branch-only format helper - the PR #19 and PR #20 precedent - ran the CI's ruff format and pushed the bytes back to this branch before the merge: the differences were the PEP 758 unparenthesized except tuples of the py315 target (the local sandbox runs Python 3.12, which cannot even parse those, so the module was authored parenthesized) and one-line reflows of calls that fit the 100-column line
